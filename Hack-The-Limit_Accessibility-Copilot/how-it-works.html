How it works

Every change is a thing you can point at.

There is no magic layer that improves a page. There is a list of small operations, each one typed, each one recorded with what it replaced, and each one undone by itself. That is the whole design, and it is why undo always works.

The parts

Seven pieces, each with one job.

Panel

The profile switcher, the controls, the change log, the undo, and the feedback. It is keyboard usable, screen reader friendly, and works at large text sizes, because a tool for this cannot be an exception to it.

Content adapter

Reads the page's regions, applies the reversible changes, and watches for parts that arrive later. It works on what changed rather than rescanning the whole page, which is what keeps it out of the way.

Preference engine

Merges four sets of settings in a fixed order: the profile, the global settings, the settings for this site, and the settings for this visit. The panel shows you which one is winning.

Learning layer

Counts the changes you make yourself and, when it spots a pattern, asks whether to save it. It records settings, never content, and never a guess about you.

Language service

Summarises, simplifies, and defines, but only when you ask for a specific passage. It sends the least it can, never form values or passwords, and always returns the source text alongside.

Companion app

Where profiles are built, named, exported, and deleted, and where the first-run questions live. Everything it holds can be exported as text or wiped in one press.

Test harness

Automated checks, keyboard walkthroughs, screen reader passes, zoom and reduced-motion runs, and speed measurements. It runs before a release, not after a complaint.

One change, in full

This is what a single change looks like.

Not a description of one. This is the actual shape of the record, and the reason field is the exact sentence the change log shows you.

operation reading / line-spacing reversible
categoryreading
targetthe article region, and every paragraph inside it
wasline-height: 1.28
nowline-height: 1.90
howa style rule, no change to the page's own markup
confidencehigh, this rule cannot alter meaning
reason shownOpened the space between lines to 1.90.
undodrop the rule, the original value returns on its own

Style before markup

A style rule can always be dropped. Rewriting the page's own markup cannot always be put back, so it comes last and only where a style rule cannot do the job.

Nothing is overwritten

When the Copilot improves a control's name for a screen reader, the author's own name is kept beside it and can be restored. It never quietly replaces what somebody wrote.

Failure is a state, not a crash

If an operation errors, the page stays as it was and the panel offers a way out. A broken change never leaves you stranded on a page you cannot use.

The rules it works under

  • It proposes, never applies. A pattern becomes a question, and the question has a No in it.
  • It says what it noticed, in plain words. You changed text size three times. Not a score, not a category.
  • It never infers a disability, a diagnosis, an age, or a health condition. Not from your settings, not from your behaviour, not at all.
  • It can be switched off entirely, and switching it off deletes the counts.
  • It learns per site as well as globally, so Plain Language on news does not follow you to a reference site.
  • Everything it has learned is visible and deletable from the panel, in one press.

The hard parts

When a page fights back.

Conflicts

Some pages have styles or scripts that undo a change the moment it is made. Pushing harder is the wrong answer, because it turns into a fight the visitor can see. The Copilot notices the change did not hold, says so, and offers a smaller one that will.

Speed

Style and structure changes should be visible within 300 milliseconds on a simple page and inside a second on a heavy one. Language work takes longer, so it runs beside the page with a progress note rather than holding the page up.

Pages that keep changing

Feeds, chats, and dashboards rebuild themselves constantly. The Copilot watches for new regions and treats only those, instead of scanning the page over and over. Switching profiles keeps your scroll position and anything you have typed.

Assistive technology

Screen readers already do a great deal, and the fastest way to break one is to talk over it. The Copilot keeps the page's own meaning, announces its own changes only where that is safe, and can be switched off for one site or one element.

The author query

The list below, worked out per page.

A proofreader marking a proof fixes what a pencil can fix. When they hit something only the writer can put right, they do not guess. They raise a query in the margin and hand it back. The Copilot does the same thing, on every page, and shows you the queries.

What it looks for

A dozen things, all of them measurable in the page with no guessing:

  • Pictures with no description at all
  • Buttons and links a screen reader cannot read out
  • Links that read as "read more" and nothing else
  • A heading level skipped
  • Form fields leaning on placeholder text
  • A page that does not say what language it is in
  • Controls hidden from screen readers but still reachable by keyboard
  • Focus order forced out of shape
  • Text under the contrast floor
  • No main region to skip to
  • Controls smaller than a fingertip
  • Media that starts itself

What it refuses to do with them

This is the part that matters, and it is the opposite of what an overlay does:

  • It does not score the page. No grade, no percentage, no badge. A number invites somebody to game it.
  • It does not call itself an audit. A dozen checks in a browser is not an audit, and saying otherwise would be the same overclaim this product exists to argue against.
  • It does not quietly patch what it found. An invented image description or a guessed button name is worse than the gap it fills.
  • It splits the list in two, so you can see which things it has covered for you and which are still broken for everybody else.
  • It admits its own reach. Twelve checks find twelve kinds of problem. There are hundreds.

Open the panel at the bottom right and choose In your way to run it here. Pressing any finding marks it on the page so you can see what is being talked about.

Said before you install it

What it cannot do.

Every tool in this space has a list like this. Most of them publish it after you have installed the thing. Here is ours first.

  • It does not work on every site. Content inside another site's frame, inside a shadow root, or drawn on a canvas is often out of reach. The panel tells you when a page is one of those.
  • It does not repair a broken website. A page with no headings does not gain headings. A picture with no description does not gain a description that means anything.
  • It does not make anybody compliant. It is a reading tool, not an audit, not a certificate, and not a defence.
  • It does not replace a screen reader, a magnifier, or a switch device. It sits alongside them and stays out of their way.
  • It does not diagnose anything and holds no health information about you.
  • It will not rewrite payment, password, legal, medical, or emergency text unless you point at that passage and ask, and even then it shows you the original.
  • A rewrite can lose detail. Every rewritten passage says so and keeps the original one press away.
